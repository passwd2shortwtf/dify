🔧 架构对比

🔴 重构前 (独立节点)

❌ 问题:
• 两个独立的节点类型: code + streaming-code
• 大量重复代码和逻辑
• 维护复杂，需要同步两套实现
• 用户体验不统一
• 在各个地方都需要处理两种节点类型

🟢 重构后 (统一节点)

✅ 优势:
• 单一节点类型: code (支持可选的流式功能)
• 代码复用，逻辑统一
• 易于维护和扩展
• 用户体验一致
• 通过配置开关控制功能

🌟 功能特性

⚙️ 配置选项

  • 🔘 启用/禁用实时日志
  • ⏱️ 缓冲超时设置 (50-5000ms)
  • 📄 最大日志行数 (100-10000)
  • 🔧 高级配置折叠面板

📊 日志功能

  • 📺 实时stdout/stderr显示
  • 🔍 日志过滤器 (全部/输出/错误)
  • ⏸️ 自动滚动控制
  • 💾 日志导出下载

🔄 向后兼容性

✅ 完全向后兼容

  • 现有的 Code 节点继续正常工作
  • 默认情况下流式功能关闭
  • 用户可以选择性启用流式日志
  • 所有现有工作流无需修改
  • API接口保持不变

📖 使用指南

在工作流编辑器中使用

  1. 添加Code节点 - 正常添加代码执行节点
  2. 编写代码 - 设置代码语言和编写逻辑
  3. 启用流式日志 - 在配置面板中开启"启用实时日志"
  4. 配置参数 - 调整缓冲超时和日志行数(可选)
  5. 运行工作流 - 实时查看代码执行日志
